# Native Quality Economy architecture

This document supersedes the upstream orchestration description for this fork.
It is explanatory; installed `AGENTS.md`, route documents and worker TOMLs are
the authoritative behavioral contracts.

## Default and deployment state

Heavy is selected without a prompt prefix. It distinguishes substantive
multi-step work from complete small leaf requests. The latter are handled
directly without a worker team, document intake or closure reporting. A small
step inside an ongoing substantive deployment does not acquire that exemption.
Explicit owner route changes remain available and last for the session.

Quality Economy is native. There is no additional opt-in profile or compulsory
personalization ceremony. Project-local safety rules and deliberate preferences
are still preserved and can override defaults according to instruction priority.

## Cost objective and capability

Optimize total model-weighted work to an accepted result. Parent-only context
reduction is not sufficient, but minimizing raw tokens is not sufficient either.
Worker calls, repeated intake, duplicated reports, unnecessary mutations and
repair work all matter. Speed is secondary, not a reason to waste serial calls.

Keep installed worker capabilities. Default Executor is Luna Max; Companion,
Investigator, Tester and Archivist retain their Luna xhigh configurations;
Senior remains Sol Medium. Parent selection remains the owner's Codex setting.
No code here estimates the exact personal subscription allowance from token data.

## Ownership

Main owns architectural, causal, scope, integration and acceptance decisions.
One Companion consolidates supporting context. Default Executor owns a coherent
production slice and ordinary repair. Tester owns independent verification and
assigned test assets, not production fixes. Archivist owns assigned canonical
documentation and one closing report. Investigator and Senior require a named
unresolved need, not a desire to fill a team diagram.

One production writer is the default; exceptional parallel writers must have
non-overlapping scope and a concrete quality or total-work justification. Shared
simulator, browser and evidence collection use one operator at a time.

## Context and handoffs

Main directly reads the six core documents, applicable instructions and
owner-named decisions. Companion inventories modules and finds affected
contracts and cross-cutting constraints. Main reads decisive contracts itself;
unclear impact expands intake. No safety invariant or explicitly required
source is omitted for an arbitrary context budget.

Initial workers receive sufficient capsules with Task ID, ownership, constraints,
exact references and rationale. Follow-ups carry deltas. The same owners handle
ordinary repair and rechecks. No status-only polling or repeated broad summaries.

A closing Archivist is reused or starts with no parent-history fork. It receives
canonical handoff documents and exact evidence pointers. The token-report script
uses session metadata, parent ancestry and the deployment ID boundary, not the
inherited transcript. Missing metadata remains an explicit reporting limitation.

## Acceptance

Acceptance is defined before code. Early independent test design is available
when risk warrants it; stable-candidate testing is the normal later step.
Executor self-checks never replace required independent acceptance. Prior evidence
requires known freshness and applicability; changed shared code invalidates the
relevant evidence. Dirty and untracked inputs count, not just HEAD.

Main inspects final requested running-product screenshots, not only a worker's
summary. An early representative frame can catch a wrong direction before final
polish. Design Velocity Mode is task-scoped and owner-enabled; deferred gates
remain OPEN. Nothing automatically promotes a candidate into production.

## Runtime and compatibility

The inherited package schema, transactional lifecycle, ownership markers,
project-local regions, worker set, token-report format and install paths are
preserved. Native policies and the versioned user command document are updated.
`runtime/release.py` points to the fork only. Source adoption preflights explicit
projects and preserves unrelated files; no updater silently falls back upstream.

The source-adoption helper is a reviewed one-time convenience, not a persistent
agent, background process or model-call layer. No scheduler or hard quota cap
has been added. Quality and consumption must still be evaluated on real work.
