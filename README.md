# Smart Orchestration 3.1.1

**Luna Max for useful work. Sol for depth. Testing without duplicate suites.**

Smart is a global Codex workflow balancing accepted quality, response time and total model work.
Main retains product, architecture, UX/design judgment and final acceptance. Coherent ordinary
work goes to GPT-6 Luna Max; GPT-6.1 Sol Low, Medium and High provide explicit stronger lanes.
Luna Medium runs approved tests without becoming the semantic reviewer.

This is instructions plus bounded deterministic helpers, not a native scheduler, permission
system or a guarantee of savings. Actual tools, model availability and owner settings bind.

## Maintenance patch 3.1.1

The model mix stays unchanged. This patch closes the legacy unscoped verification bypass,
prevents known stalled Sol owners from being routed back to the same preset, separates nested
readback from new scheduling authority, inherits parent sandbox settings, resolves worker guides
from the installed location, and shortens the duplicated global bootstrap. Low-capacity testing
and review have an explicit serial handoff. Patch-specific release notes and pinned CI actions
keep maintenance predictable. See [audit details and validation](docs/v3.1.1.md).

Use it for the work itself. Research, writing, planning and administrative tasks need relevant
evidence, not invented software tests. No routine workflow audits, model research, reinstallations
or retuning are required. Revisit the workflow for observed problems or explicit update requests.

## What changes in 3.1

| Responsibility | 3.0 | 3.1 |
| --- | --- | --- |
| Ordinary implementation / bounded unknown bug | Sol Medium | Luna Max |
| Moderate complexity / adaptive tools | Sol Medium | Sol Low |
| Deep implementation / interacting logic | Sol Medium or xhigh | Sol Medium; High for serious work |
| Independent semantic review | Tester / Sol Medium | Reviewer / Luna Max; Senior Reviewer / Sol High for deep or critical risk |
| Approved test execution | Mixed with semantic review | Tester / Luna Medium, separate evidence duty |
| Bounded causal investigation | Sol Medium | Luna Max; appropriate Sol when uncertainty/risk warrants it |
| Known extraction / GUI recipe / prescribed bulk work | Luna Low / High | Luna Max, in coherent batches |
| Open Smart worker budget | Up to four | Up to five, only with verified independence and actual capacity |
| Main while workers execute | Disjoint critical-path work | Preserved, without duplicating worker work |

The inexpensive model is not selected at any cost. Start directly with Sol when uncertainty,
weak observability or consequences make that sensible. Do not force serious work through cheap
failures. Conversely, an unknown but bounded reproducible bug need not automatically incur Sol.

## Fixed presets, not a standing team

| Named role | Model / effort | Responsibility |
| --- | --- | --- |
| Main | Owner-selected; Sol Medium recommended | Judgment, small direct work, integration, acceptance |
| `routine_executor` | GPT-6 Luna Max | Ordinary implementation, bounded unknown bugs and bulk transformations |
| `default_executor` | GPT-6.1 Sol Low | Moderate work, adaptive tools and bounded escalation |
| `deep_executor` | GPT-6.1 Sol Medium | Deep implementation and interacting-component diagnosis |
| `senior_executor` | GPT-6.1 Sol High | Serious or critical-risk work |
| `reviewer` | GPT-6 Luna Max | Independent ordinary semantic review |
| `senior_reviewer` | GPT-6.1 Sol High | Independent deep / critical-risk semantic review |
| `tester` | GPT-6 Luna Medium | Approved test execution, waiting and reporting |
| `investigator` | GPT-6 Luna Max | Bounded causal investigation |
| `simple_executor` | GPT-6 Luna Max | Known GUI journeys, extraction and established operations |
| `companion` / `archivist` | GPT-6 Luna Max | Exact lookup / authorized compact checkpoint |

These are on-demand presets, not eleven concurrent agents or a new manager layer. Named Sol
levels are real files, not an instruction pretending to switch a running agent. Verify the
actual model and effort in the client. Unsupported Max is not silently relabeled xhigh; no
automatic Fast, Astra or permission expansion. Explicit parent/profile settings remain.

Main can finish a tiny understood change directly. For substantive delegated work, give the
outcome and constraints rather than pre-solving the entire patch. Select Sol Low when a stronger
family is useful but the problem is bounded; Medium for substantial interacting logic; High for
serious depth or consequences. Security, payments, authorization and irreversible data changes
justify a higher-risk route even when the diff is small.

One evidence-based correction of the same defect without progress triggers appropriate Sol/Main
diagnosis. Preserve the original failure and attempted fixes. Do not cycle through every effort
level or spend unlimited cheap retries. Ordinary compiler errors with progress can stay with the
same owner. Max does not guarantee fewer errors, lower latency or lower total allowance use.

## Large test suites: execution is not judgment

Tester/Luna Medium owns approved commands, process waits, raw logs and compact receipts. It does
not choose inadequate gates, write production fixes, weaken assertions, accept snapshots or
claim semantic sign-off. Test design, causal debugging and flakiness investigation go to Luna Max
or an appropriate Sol role. A green suite is evidence, not proof of correct product behavior.

During editing, use focused decisive checks. At integration run every required complete suite
on a stable integrated candidate. Do not run 1,000+ tests after every small edit, or independently
repeat the same applicable run in Main, writer and reviewer. Required fresh/full tests still win.
Relevant source, dirty/untracked inputs, test/config/lockfiles, toolchain, environment, target and
command/scope must remain applicable before reusing proof. HEAD alone is not a dirty-tree identity.

One test owner controls each process. Use supported runner parallelism within CPU/RAM limits;
shard only with isolated ports, accounts, databases, caches and output paths and account for every
expected shard. Five agents do not mean five simultaneous full suites. A timeout while a command
continues is not permission to restart it. Keep passing-test streams out of Main, but preserve
complete raw evidence and the first failure.

Exit zero with zero tests, missing shards, collection errors, unexplained skips, incomplete runs,
weakened coverage or an unresolved flaky failure is not a valid passing gate. The receipt records
candidate/scope, exact command/cwd/environment, completion/exit status, duration, available totals,
shards, logs, freshness and remaining obligations. Unknown values are not invented.

See [test execution](codex_workflow/testing.md) and [verification](codex_workflow/verification.md).

## Parallelism that remains safe

Dispatch ready independent work before waiting. Start with two useful branches; grow to five only
when actual work, capacity and resources justify it. The primary thread is excluded. Unrelated
threads and lower explicit caps count. Main may execute a disjoint critical path, not the same work.

Different filenames do not prove independence. Account for canonical workspaces, shared modules,
read/write dependencies, lockfiles, builds, accounts, ports, servers, databases and browser/desktop
sessions. Unknown impact serializes affected work. Whole-tree checks cannot race active writers.
A genuinely immutable isolated preview can overlap another independent implementation.

Reserve one shared future semantic-review slot when needed, not one per writer. Reviewer and
Senior Reviewer can serve that queue; procedural Tester cannot replace them. Preserved capacity
of three can still support two isolated writers and serial review. After completion preserve
results and release resources, then observe native closure before relying on a freed slot.
A final message is not native closure. At capacity errors reconcile once; retry only after an
observed change. Never close unrelated/active work or raise owner limits automatically.

## Review, design and acceptance

Every writer self-checks, including Main. Independent semantic review follows meaningful risk or
explicit gates, not the mere existence of a worker. Low-risk reversible copy/style edits with
decisive checks need not create Tester plus Reviewer. Main is never its own required independent
reviewer. Higher-risk/deep review starts at Senior Reviewer rather than a cheap rubber stamp.

Initial review covers original requirements and the complete bounded diff in independent context.
The same reviewer may check complete correction deltas against a recorded baseline, including
Main changes, affected dependencies and original findings. New reviewer, changed contract, missing
baseline or unknown impact requires full bounded review. Reuse valid test evidence; never cache
away mandatory fresh gates. Preserve distinct procedural-test and semantic verdicts.

Hold candidate inputs and target during verification. Release before repair; re-hold and refresh
affected evidence. Missing proof remains UNVERIFIED and drifted proof STALE. Main inspects actual
visual evidence, groups actionable findings and stops at accepted quality rather than endless
optional polish. Use an early visual frame for a genuinely new direction, not every spacing edit.
Acceptance, commit and deployment remain separate authorities.

## Installation or update

For the current published version, send Codex:

```text
Install Smart Orchestration from https://github.com/7Eterius/codex_smart_orchestration. Resolve the current HEAD commit SHA of main and download/extract that exact source snapshot outside my projects. Do not use GitHub Releases or historical dist archives. Read codex_workflow/operate/smart_install.md. With Python 3.11+, run codex_workflow/runtime/smart_install.py --package-root codex_workflow without --apply first and inspect the preview. If clean, run the same command with --apply, then --check. Preserve unrelated Codex configuration and every project file. Stop on conflicts, never force changes. Do not quit, relaunch or wait for Codex to exit. Report version, source commit, fingerprint, backup, configured concurrency cap and disk result; tell me to restart Codex manually. A disk check is not live runtime proof.
```

Restart Codex manually and start a fresh conversation after successful preview/apply/check.
Select the recommended Main model through the supported selector; installation does not switch
an already-running conversation. Pin the inspected source commit; do not assume a branch or archive has the requested version.

**Existing explicit settings are preserved.** Fresh installs without a cap receive five and
Luna Max generic child defaults. An existing cap of two, three or four remains unchanged and is
reported as lower capacity. Deliberately selecting five in the actual client is a separate owner
action, not a hidden installer change. Named roles override the retained generic fallback.
Customized managed files cause conflicts, not forced overwrites. Exact rollback preserves prior
bytes/settings and the backup trail. No project bootstrap or per-project database is required.

## Validation and evaluation

```bash
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
python3 -m compileall -q codex_workflow scripts
```

CI covers Linux Python 3.11/3.12 and macOS Python 3.12, current routing/preset contracts,
read/write/resource conflicts, review capacity, holds, native lifecycle observations, installer
safety and exact historical upgrades/rollback including 3.0.1. The archived 2.7.1 suite remains
unchanged and separate from current tests. Git history is required in CI; unavailable history is
not a passing historical test. Deterministic tests are not live model qualification.

Measure elapsed time to accepted result, total model work, correction rounds, quality, test
wall-time/duplicate runs and observed subscription allowance on comparable tasks. API token prices
are not a direct subscription allowance formula. Max may use more reasoning than Low; concurrency
can increase simultaneous consumption. Savings and speed improvements require real measurements.
