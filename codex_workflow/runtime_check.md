# Targeted capability checks, not a global qualification ceremony

A correct disk installation is not proof of the active session's roles, models, permissions,
scoped history or thread lifecycle. Test only a mechanism whose uncertainty actually blocks
work. Do not spend a project session repeatedly qualifying basic features.

Main can finish direct tasks without subagents. For named delegation, use one harmless bounded
probe when needed; verify runtime metadata where exposed, not the worker's self-description.
Unavailable per-run metadata remains unknown. Follow native tool schemas, not guessed keys.

For parallel work verify actual cap and open handles, scope/resource isolation, completion
notifications and supported closure. A final message is not reclaimed capacity. At a capacity
failure reconcile known handles once; retry only after observed change. Never raise owner caps,
close unrelated work or fake successful cleanup. Lower-cap clients use fewer workers or serial
review. Direct named delegation does not require nested delegation.

Routine/Default may dispatch one Tester only with explicit Main authority and observed native
support. Otherwise Main dispatches the same independent reviewer. No simulated nested tree.
Persist results before closure and keep shared browser/server resources separately owned.

Installation remains preview/apply/check, manual restart, then fresh conversation. The disk
check reports configured recommendations, not actual model selection. Preserved older generic
child models or lower caps are visible configuration facts, not automatically corruption.
