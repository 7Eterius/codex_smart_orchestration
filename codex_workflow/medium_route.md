# Medium Route - explicit alternative

Use only after the owner explicitly selects Medium. Heavy remains the default
for a new session. Questions and small bounded leaf work use the direct fast
path without support workers, documentation intake or closing token report.

## Ownership

The main owns planning, root cause, implementation, production repair,
verification, integration, acceptance and communication. Medium does not
delegate production or verification. Use only Companion, Investigator and
Archivist. Do not select this route automatically because work is visual.

Optimize total model-weighted work to an accepted result, not just main context
or elapsed time. Keep owner requirements, safety, necessary context and test
assertions intact. Do not promise a cheaper result merely from the route name.

## Entry and Packages

Complete the shared first-entry Companion and `agent_docs/` contract in
`AGENTS.md`; reuse prior intake and the same persistent Companion across route
changes. Keep a compact Direct/Companion/Investigator relevance map. The main
reads decisive source and affected module contracts, Companion consolidates
supporting project evidence, and Investigator fills only a named unresolved
project or external evidence gap. Broaden intake when dependency impact is
unknown. Do not duplicate discovery or restate the complete owner brief.

Choose a unique lowercase underscore-safe deployment ID and include once in
the first commentary message of substantive deployment:

```text
<!-- codex-workflow-deployment-start: <deployment_id> -->
```

Every initial capsule begins with **Task ID**:

| Role | Capsule parts |
| --- | --- |
| Companion | **Project Context Scope**; **Context Task + Goal**; **Main-Agent Context Guidance** |
| Investigator | **Investigation Context**; **Evidence Question + Goal**; **Main-Agent Investigation Guidance** |
| Archivist | **Documentation Context + Audience**; **Documentation Task + Goal**; **Main-Agent Documentation Guidance** |

Give sufficient exact references, authority and constraints, normally with
`fork_turns="none"`. Follow-ups repeat Task ID and changed capsule parts only.
Reuse unchanged evidence; do not ask for tiny lookups or repeated broad summaries.
Batch independent known-input work and synthesize once. Do not poll workers or
request status-only updates. Preserve ownership and dependent mutation order.

## Acceptance

Define acceptance before implementation. Run affected checks during development
and required gates on the stable candidate. Reuse earlier evidence only with
known unchanged inputs and applicability; unknown freshness requires a recheck.
Changed shared code invalidates relevant prior evidence. Include dirty-tree and
untracked inputs, not only HEAD. Never weaken assertions or claim unrun checks
passed. Report external blockers instead of repeating unavailable operations.

For UI work, inspect the actual running product and final requested screenshots
against the owner contract. Serialize shared simulator/browser state and capture
from one identified candidate and isolated data source. Builds do not establish
visual quality. Report missing observations or image-delivery limits honestly.

Design Velocity Mode applies only when explicitly activated for this task.
Deferred gates stay OPEN; other work retains all applicable quality and safety
gates. Do not reopen accepted designs or promote a proof beyond its checkpoint.

## Closure

Before completing, pausing or blocking a substantive deployment, update
`agent_docs/project_progress.md`, `agent_docs/project_diary.md`, and
`agent_docs/latest_session_work.md`, keeping them concise and canonical. Follow
`~/.codex/codex_workflow/archivist.md` once. Relay the handoff and exact
six-column `$deployment-token-report` with limitations. New deployments get new
IDs. Preserve owner work and restrict Git mutations to explicit task authority.
