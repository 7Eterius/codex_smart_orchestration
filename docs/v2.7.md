# 2.7.1: evidence-bound handoffs with safer review dispatch

## 2.7.1 patch corrections

The reviewed 2.7 source exposed one more economical handoff edge case: a gate explicitly due
at acceptance was always classified as pending during worker handoff, even when it was already
reported failed on the current candidate. 2.7.1 distinguishes **not due yet** from **known bad**.
A known current failure goes back to the writer before independent review; unrun/deferred or
otherwise later-stage obligations remain pending for their proper owner. When current identity
is supplied, a claimed failure with missing/stale binding is reported as unverified/stale rather
than treated as a current defect.

2.7.1 also makes the existing narrow Main-only bridge exception single-writer safe. Main never
mutates the same candidate concurrently with an active worker. If an indispensable bridge write
touches the worker's scope or declared evidence inputs, ownership is paused/transferred first;
the resulting candidate and exact delta are handed back, affected evidence is invalidated, and
same-reviewer delta optimization is used only when that bridge change is fully accounted for.
Unknown impact requires full bounded review.

No model, effort, role, permission, capacity or orchestration-mode change is introduced.

## Scope

Keep the single adaptive loop, eight roles and delegation-first design. Main baseline remains
GPT-6.1 Sol Medium; Senior remains GPT-6.1 Sol xhigh. All model/effort/sandbox/delegation
settings are unchanged. Main still owns product, architecture, design judgment, inspection
of actual visuals and final acceptance. Workers implement and repair. No new execution mode,
manager, task database, model catalog, permissions, capacity or telemetry service.

## Correct the preflight, not just its prose

The 2.6 challenge helper mixed handoff readiness with acceptance: an addressed finding still
blocked the handoff needed for independent recheck, and every required gate was evaluated
before the reviewer could run. Optional handoff/accept phases now separate those questions.
These are stages in the same workflow, not competing orchestration modes.

At handoff, addressed findings need evidence and remain pending resolution. Gates explicitly
due at acceptance remain visible as pending; no gate is waived. At acceptance every required
gate must hold and every blocking finding must be resolved. Omitting phase keeps legacy
acceptance-strict behavior. Honest BLOCKED handoffs never require a fake clear result.

The helper now validates the entire input before reporting any contradiction. Boolean/float
schema values, ambiguous/traversal paths, duplicate row identities, malformed later rows,
non-finite JSON numbers and oversized inputs fail closed. An empty set of obligations is
unverified rather than an empty success. These are reproducible code defects/limitations;
there is no claim that they caused a particular user's earlier usage pattern.

## Bind evidence and show the next step

Optional current attempt/contract/candidate/target and per-result basis fields expose stale
or absent bindings. Passing statuses alone do not establish current evidence. Optional
--manifest reuses candidate.py for a fresh read of explicitly scoped local inputs; a
mismatching declared candidate is an error, actual drift is stale, not a pass. No new source
scanner or dependency graph is introduced. Model, author and authority fields remain claims.

The response carries a bounded batch, total/omitted counts, pending obligations and a specific
next action. Mechanical repairs stay with the current worker. Scope conflicts, unknown
attribution and protected decisions return to Main. No destructive reset or fabricated
concurrent attribution is suggested. CLEAR never means semantic correctness or acceptance.

A deliberately unchanged deliverable may satisfy an explicitly approved outcome, backed by
evidence. This avoids forcing pointless edits merely to make a file look changed.

## Ask what matters, verify what actually ran

Main can name a few must-answer questions in the original capsule. Workers answer with exact
evidence or report unknown; they do not rely only on their own willingness to flag uncertainty.
No numeric confidence threshold is introduced. Evidence-backed questions do not transfer
product/design authority to the worker or add a mandatory question round to every task.

Tester now explicitly runs required gates whether or not it has a suspected defect. Optional
extra probes remain targeted. New critical tests should exercise real entry points and
meaningful negative controls where practical, not a copy of the implementation or a test
that fails only because its setup is broken. An observer must report failures truthfully.
Independent reviewer context, repair-bound evidence and Main's visual judgment remain distinct.
An accepted design violation can block; optional taste and cleanup cannot.

## Save work by removing false obligations

Known authoritative paths can be read directly after applicable instructions, without an
index/explain ceremony. Existing context indexes are for discovery, not mandatory detours.
Notes and unrelated changes do not invalidate focused evidence; actual dependency drift does.
Keep logs and read the exit code/failure blocks before summaries rather than rerunning only
to reconstruct lost output. At repeated same-defect repair, reassess diagnosis/ownership
within authorized models instead of paying for endless retries. No automatic escalation.

The one-slot reviewer fallback is explicit again: preserve repair context, release the writer
through supported native lifecycle, then dispatch Tester. No safe path means checkpoint, not
omitted independent review or silently expensive Main implementation.

## Installation and compatibility

The existing pinned-main preview/apply/check procedure is unchanged. challenge.md is an
on-demand installed guide, not always-loaded prompt text. Existing model selections, project
files, permissions, capacity and unrelated configuration remain protected. Restart manually
and open a fresh conversation after updating; source publication alone changes no local client.
Schema-1 records remain usable, but ambiguous/malformed inputs and empty obligations now fail
closed. Without current identity, output explicitly reports that binding was not checked.

## Validation

Retain all historical tests and archived baselines. New tests cover whole-record validation,
legacy behavior, stage transitions, stale identity in every dimension, questions, batch limits,
actual CLI exit codes, candidate-helper integration and original 2.6 false-clear regressions.
The exact 2.6 -> 2.7 -> no-op reapply -> rollback test checks all role settings, owner config,
project preservation and protection of a locally edited new guide. Source tests are not native
Codex compliance, independent code review, design-quality measurement or allowance savings.
