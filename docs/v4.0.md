## What changed and what deliberately did not

| Superpowers practice | Smart 4.0 adaptation |
| --- | --- |
| Observe, trace, compare, hypothesize, then repair | Smallest safe causal probe; reusable by the current owner, no forced Investigator handoff |
| Scaled brainstorming with an approval gate even for bounded work | Targeted discovery only for real ambiguity; clear authorized work proceeds; protected choices retain approval |
| Detailed implementation plans including complete code | Lean requirement/decision/interface/deliverable plans; workers solve implementation rather than transcribing Main's patch |
| Fresh per-task agents and persistent progress ledger | Fresh unrelated context, retained concrete correction context; compact identity-bound checkpoint only for long/handoff work |
| Task review of specification and technical quality | Both dimensions in one risk-based independent pass; no universal reviewer for trivial edits |
| RED/GREEN/REFACTOR | Real testable behavior first; characterization for refactors and honest alternatives where TDD is inappropriate |
| Bounded repair loop and scoped re-review | Earlier stalled-owner escalation; three failed causal fixes OR three task repair waves trigger replanning, never false completion |
| Evidence before completion | Inspect actual current-candidate evidence; reuse valid receipts unless fresh/full gates require execution |
| Native-first worktrees and complete base-to-head review packets | Reuse verified isolation; include relevant dirty/untracked inputs and safe finish/cleanup authority |

The actual SDD skill already batches small same-shape tasks and avoids duplicate valid test runs.
Smart preserves those ideas rather than presenting them as novel. Its broad final-review and
five-round adjudication rules are not adopted verbatim: optional polish stays nonblocking, but a
real required/security/correctness failure cannot be parked as accepted because the budget ended.
Speculative assertions such as every three-fix failure proving wrong architecture are not imported.

The upstream review-package script correctly uses a recorded BASE instead of HEAD~1. Smart also
requires dirty/untracked deliverables to be accounted for. The sdd-workspace helper scopes storage
by plan basename; Smart checkpoints use canonical repo/task/requirement identity so equal basenames
cannot be mistaken for the same job. A directory name alone is not cleanup ownership evidence.
No automatic .gitignore commit, broad rm -rf, dependency reinstall or isolation-denied fallback is
introduced. Explicit finish authority replaces fixed merge/PR menus when the user already chose.

All eleven named model/effort presets remain as in 3.1.1, including inherited sandbox settings.
Main remains owner-selected; no installer quietly changes Luna Main to the recommended Sol Medium.
The five-worker ceiling, conflict checks, independent verdicts, candidate identity, no-op install,
exact rollback and protected owner configuration are retained. Existing narrowly authorized verifier
nesting remains compatible, but Main dispatch is preferred and duplicate reviews are forbidden.

## Installed components

The Main policy now selects the appropriate method once. New lazy-read guides:
[planning](../codex_workflow/planning.md), [debugging](../codex_workflow/debugging.md),
[branches](../codex_workflow/branches.md), [economics](../codex_workflow/economics.md).
[Testing](../codex_workflow/testing.md) adds appropriate RED/GREEN and characterization.
Implementation, investigation, Tester and reviewer prompts link the relevant methods without
loading every guide into every worker. The bootstrap stays short and reads the full policy only
for substantive Main work. No new agent, manager, daemon or compulsory per-command ledger exists.

`runtime/delivery.py` is an optional pure adviser, separate from model/scope allocation. It consumes
small supplied records and cannot spawn agents, inspect native quota, authenticate facts, lock
files, spend money or accept work. Existing `allocation.py`, `candidate.py`, `boundary.py` and
`challenge.py` remain the mechanisms for their original responsibilities.

### Practice selection

```json
{"operation":"prepare","facts":{"domain":"code","kind":"bug","size":"small","clarity":"clear","risk":"material","behavior_change":true,"testable":true,"isolated":false,"long_running":false}}
```

Domain is code/noncode; kind is feature/bug/refactor/mechanical/research/writing/operations; size
is small/medium/large; clarity clear/ambiguous; risk low/material/critical. Flags are strict booleans.
Optional tdd_required preserves an explicit requirement: untestable required TDD requests test
strategy resolution, not an exception. The adviser returns plan depth, needed guides, TDD choice
and an isolation recommendation, not write or Git authority.

### Next-batch budget

```json
{"operation":"budget","facts":{"quota":"low","requested_workers":5,"available_slots":3,"independent_ready":2,"mandatory_gates_pending":true}}
```

Quota is available/low/exhausted/unknown based on available observation, not a fabricated percentage.
Unknown quota starts conservatively without demanding a usage audit. available_slots may be null,
which cannot establish capacity. Actual allocator scope/reservation/cap checks still apply.
Optional limit is {unit, maximum, spent, committed, next_estimate, observation_current}. Units are
tokens/credits/seconds/requests, never converted. next_estimate covers the ENTIRE proposed batch
including verification. It is nullable; stale observations and unknown estimates cannot certify an
explicit budget. Parallel/in-flight work is included in committed. No hard native spending cap is
claimed. Missing budget data is not zero cost. All branches preserve required gates.

### Cumulative repair breaker

```json
{"operation":"recover","facts":{"task":"reader-hydration","defect":"filter-flash","previous_owner":"routine_executor","failed_fixes":2,"repair_rounds":2,"same_defect_no_progress":true,"new_evidence":true,"blocking":true,"authority_needed":false,"budget_exhausted":false}}
```

Counts carry across worker/model changes. Three failed causal fixes for a defect OR three completed
task fix/re-review waves stops automatic patch dispatch. Earlier no-progress triggers appropriate
Sol/Main diagnosis. The helper returns accepted=false on every path; exhausted quota cannot turn
an unresolved blocker into success. Main may resume only after a recorded new approach and bounded
budget within authority. The helper cannot detect someone falsifying/resetting its supplied counts.

```text
python3 -B codex_workflow/runtime/delivery.py --input /private/existing-task-facts.json
```

Exit 0 is bounded advice to proceed/record optional work, 1 means inspect/replan/checkpoint/decision,
2 malformed or unreadable input. None is acceptance, permission or proof of runtime behavior.
Unknown fields, booleans used as counts, nonfinite/negative values, duplicate keys, oversized and
excessively nested input are rejected. These records are optional, not a task admission ceremony.

## Completion and recovery contract

A completed claim names the actual candidate, what was verified, original evidence and remaining
limits. Green tests do not establish build, deployment, visuals or live installation. A regression
test written after a fix can be validated against a safe known-bad baseline, but is not mislabeled
as test-first. Existing valuable code is never deleted solely to enforce TDD chronology.

Large features get a single integrated view of contracts and findings, not a repeated full-suite
run per reviewer. New integration changes still invalidate affected proof. Worktree cleanup uses
recorded ownership and checks ignored/untracked files and preserved reports; another agent's path
is not yours. Explicit cap adoption remains the same backed-up opt-in documented in README.

## Validation and evaluation limits

New decision tests cover practice selection, explicit TDD constraints, bounded concurrency, unknown
and exhausted quota, committed spending, stale budget observations, cumulative breakers and CLI
failure modes. Integration tests preserve model choices and install all declared guides/helper and
license; exact 3.1.1 upgrade/no-op/rollback joins the historical baselines. Existing 3.0.1/3.1.1
safety counterexamples stay active. Historical 2.7.1 tests remain a separate unchanged reference.

These tests establish deterministic behavior, not native agent compliance with prose. Evaluate
real work separately with matched task/candidate/acceptance conditions: first-pass acceptance,
time to accepted result, total model work, repairs, duplicate suites, lost-context redispatches,
and observed allowance when available. Do not infer quota from token prices or claim a percentage
speed/cost improvement from source CI. Do not tune routing based on anecdotes alone.

Install from a complete pinned source snapshot, preview/apply/check, preserve owner/project settings
and backups, then restart manually with a fresh conversation. Do not co-activate a second
Superpowers orchestration bootstrap for the same work; report conflicts and seek authorization
before disabling/removing any existing plugin. Ordinary work needs no recurring workflow audit.
