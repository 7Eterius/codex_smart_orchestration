# v1.5.2: main-owned design, worker implementation

This is a focused authorship clarification, not another route or model change.
The selected main model owns product, UX, interaction and visual design throughout
screen work: define the direction, inspect a running first composition, critique
it specifically, and directly review final visual evidence. It is not merely a
coordinator assigning "make it beautiful" or an approver of worker prose.

## Ownership and efficiency

The main's compact brief establishes purpose, information hierarchy, composition,
key states, interactions and visual direction using relevant accepted references.
A settled owner brief can supply these decisions; do not rewrite it or restart
an accepted design competition. Novel design is not a simple task just because
the code diff is small. Design-only requests do not authorize implementation.

Executors implement the settled brief, choose ordinary details within agreed
patterns/tokens and handle routine coding repairs. They may propose alternatives,
but unresolved or materially changed design returns to the main. Transferred
Senior implementation does not transfer design authorship or owner approval.
Luna Medium/High/Max and Sol assistance remain as previously configured.

For new running compositions, main reviews an early frame before substantial
polish, then final evidence after relevant changes. Missing visual access remains
unverified; generated mockups are not evidence that a product ran. Batch related
visual corrections rather than involve main on every shell output. Small approved
tweaks reuse existing direction, with no extra designer agent or mandatory study.

Behavior/accessibility verification, main design judgment and required owner
approval are distinct. Tester reports actual evidence and observed deviations,
not aesthetic acceptance from a build/test pass. Archivist preserves design
rationale/evidence and distinguishes proposed, main-reviewed and owner-approved
states. It must not invent the owner's approval.

## Scope

The canonical policy stays below 1,500 whitespace-delimited words, each role below
300. The design section is 150 words and replaces one redundant visual sentence.
No new always-loaded design document or agent role. All eight model/effort pairs,
non-instruction role settings, runtime Python, installer, diagnostics, capture,
verification guide, reporting skill and configuration defaults remain unchanged.
This patch does not modify Materia/RussianReading or any local Mac installation.

## Representative manual scenarios (not an automatic benchmark)

| Request | Expected behavior |
| --- | --- |
| Design and implement a new Materia screen | Main defines the experience, worker implements, main critiques actual frames |
| Implement the approved grouped Accounts direction | Reuse owner decisions; no renewed A/B competition |
| Adjust an agreed spacing/label | Bounded edit/check; no fresh design study |
| Worker needs to change hierarchy to simplify layout | Return proposal to main, do not silently redesign |
| Design concept only | Deliver the agreed concept, no unrequested product mutation or running-product claim |
| Screenshots unavailable but tests pass | Report functional evidence separately; visual acceptance remains unverified |

Use the existing global installer and backups. A CI package or PR is not a
published GitHub Release. Required owner review and release gates remain intact.
