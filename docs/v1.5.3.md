# v1.5.3: opt-in reporting and evidence-led efficiency

## Evidence and scope

Owner-provided dashboards suggest substantial parent-model activity and a small
Archivist footprint in sampled tasks. Tool/skill invocation counts are not token
costs; incomplete or differently scoped dashboards are not before/after benchmarks.
No complete owner JSONL run, matched task outcomes, or billing ledger was supplied.
The code and synthetic records support a reporting fix, not a correction factor
for old screenshots or a claim of five workdays at unchanged productivity.
Private screenshots, raw logs and account data are not included in this repository.

## Workflow changes

Reporting is now opt-in, never an acceptance or closure gate. Preserve a cheap
entry marker for retrospective scoping, but do not auto-invoke the reporting skill
or spawn an agent just to print a table. `allow_implicit_invocation: false` prevents
implicit skill selection in supporting clients. Explicit requests remain supported.
Main can run the local script for its known root plus marker, or explicit start/end;
an existing Archivist can still resolve its parent. No extra Archivist is required.
Unknown scope or missing telemetry produces a limitation, not repeated retries.

Archivist still maintains useful project handoffs, history and decision rationale.
It no longer needs a usage table to complete that work. Product/design ownership,
independent testing, owner approval and relevant accessibility gates stay unchanged.

Workers collect build/navigation/screenshot evidence where tools and permissions
allow it. Return related evidence at decision, blocker or acceptance boundaries,
not every shell line. Main directly judges the relevant artifacts without routinely
repeating their collection. Necessary design and architecture reasoning is not capped.
There are no model/effort changes, fixed subagent-cost targets, smaller context-window
settings, automatic compaction, extra roles or new external services. Computer Use
and Computer History permissions remain exactly as the owner configured them.

## Corrected local accounting

The old script summed `last_token_usage` for every notification. It could count a
re-emitted snapshot twice. A public report in the official Codex repository describes
rate-limit updates that re-emit unchanged counters; the synthetic test independently
reproduces the weakness in this consumer. Neither proves that a particular owner's
run contains duplicates.

The new script:
- Reads cumulative input/cached-input/output counters in file order and uses the
  last pre-window record as a baseline, not as new work.
- Ignores unchanged cumulative snapshots. Equal-size real requests still count
  separately when their cumulative totals advance.
- Reconciles each positive delta with its last-usage record. Missing counters,
  unexplained resets, out-of-order timestamps or unreconciled changes fail clearly.
  Last-only logs are no longer silently interpreted as unique requests.
- Excludes pre-creation copied history from child work, retaining it only to seed
  a baseline. Explicitly forked sessions without a usable baseline are rejected.
- Counts distinct child session IDs, not repeated task labels. Missing child usage
  is omitted with a partial-coverage warning, not presented as zero-cost execution.
- Freezes the default cutoff before indexing. The window describes usage-notification
  timestamps, not service billing timestamps. Do not sum overlapping windows.
- Keeps cached input as a subset of total input and does not add reasoning output
  a second time. It is not an API or subscription pricing calculator.

The six-column Markdown table remains for compatibility. `Rollouts` now explicitly
means reconciled usage updates, NOT guaranteed unique API requests or user messages.
The script prints a mandatory interpretation/window note to stderr alongside any
warnings; do not suppress that note in the handoff. JSON schema 2 adds accounting
method, scope/coverage, unchanged-snapshot counts and per-session recorded model/effort
contexts. Role names do not prove model use. Context metadata is recorded intent,
not independent server/billing evidence, and missing values stay null.

This is deliberately conservative. It may refuse telemetry from an unsupported
client/schema rather than produce a reassuring but ungrounded total. Timestamp-
rewritten forks or unlogged requests cannot be reconstructed reliably. Missing
sessions cannot be discovered from absence alone. Available records are not proof
of complete account coverage. A report error never makes valid product work fail.
The local Python computation makes no model or network calls, but asking an agent
to invoke/read it still has model overhead. Smaller corrected numbers alone are
NOT actual consumption savings.

## Compatibility and validation

All existing runtime/installer/configuration code and non-instruction role settings
remain byte-for-byte unchanged from v1.5.2. The reporter is contained in its existing
skill directory; no new install-time dependency or script runner is introduced.
The existing global installer updates the owned skill with normal backups and
refuses customized-file replacement. No project installation is required.

The eight original report tests now write cumulative counters into their fixtures;
all original assertions remain. The existing v1.5.2 test suite tracks the current
version for current-state readback and excludes only the three intentionally changed
reporting-skill files from its old byte-equality check. Runtime, resources, remaining
skill files, all role settings and the verification guide retain their checks.

Run all prior suites plus `python3.11 -B scripts/test_v153.py -v`. The new tests cover
snapshots, equal real requests, pre-window and fork baselines, missing/reset counters,
reasoning/cache accounting, explicit root invocation, scope/cutoff, unknown context,
opt-in policy and exact v1.5.2 upgrade/reapply/rollback. CI reconstructs the baseline
from merged commit `2ca52d48f29c79b24d6eb0e0393f473b60ba89fc`, validates its complete Git
tree, and tests only disposable homes. Source validation needs full history; the
installable package does not require Git.

Live task quality, actual parent-operation reduction and allowance savings remain
unmeasured. Keep the same model baseline and compare accepted tasks including repair
and owner-rejected visuals. Do not reduce a verification gate to improve a report.
