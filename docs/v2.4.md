# 2.4.0: main-led judgment, delegated execution and repair

## Why this version

The owner observed substantial execution remaining with main despite economical named
workers. The desired change is stronger delegation, not weaker design judgment or another
manager layer. Privacy-safe usage profiles identify investigation targets; opaque tools,
missing prices and different workloads do not establish waste or achievable savings.

## Changes

The main policy and installed developer-instructions bootstrap now make delegation the
execution default, including small established edits and repairs from main's review.
A small diff, familiarity, latency or unavailable nesting cannot justify main taking over.
Main does not pre-write the entire implementation for a nominal worker to paste.
The optional allocation classifier also delegates tiny settled edits/operations rather
than returning main. Judgment, risk-based review and capacity safeguards remain intact.

Main retains product/architecture/UX/visual decisions and detailed result assessment.
An on-demand design guide specifies the loop: main settles the brief; a Luna worker
implements and returns running evidence; main inspects it, sends grouped findings back
as correction tasks, and rechecks the repaired candidate before accepting. Worker or
Tester success never replaces actual main visual assessment or owner approval.

Simple is explicitly responsible for complete mechanical browser/GUI journeys and low-risk
correction tasks. Routine remains the normal implementation owner, including settled
design implementation. Reuse a suitable worker through corrections and short evidence
collection instead of introducing a third worker only to relay screenshots.

Main may answer, write authorized decision briefs and inspect decisive evidence. Main-only
execution is limited to explicit user overrides or observed, narrowly authorized tool/
permission boundaries, stated once. The rest returns to workers; unavailable capability
remains a limitation. There is no sandbox widening or fabricated browser access.

## Preserved architecture and protections

One adaptive loop and eight named roles remain. Model/effort assignments, parent settings,
generic fallback, permissions and capacity are unchanged. No additional scheduler, manager,
base-model instruction override, telemetry service or per-command ledger is introduced.
The instruction policy is not a native tool interceptor or a role security allowlist.

Candidate holds, protected independent verdicts, risk-adaptive review, required fresh gates,
source/owner protections and native thread release remain intact. Source caches/backups
are not swept. The installer still uses pinned main source, preview/apply/check and a
manual restart; existing release publication remains gated on the complete CI matrix.

## Validation scope

New regression coverage checks delegation clauses in both activation surfaces, main's
actual-result/review/correction responsibilities, narrow fallback boundaries, worker
contracts, model invariance, prompt budgets and design-guide installation/integrity.
An exact archived 2.3 installation upgrades to 2.4, reapplies without writes and restores
exactly, preserving owner configuration and project bytes. Historical migration tests
remain, with current-version assertions separated from pinned historical baselines.

These are source and installation checks, not live Codex qualification or measured savings.
Native execution/model metadata and actual behavior remain UNVERIFIED until observed.
No native scheduling or real-browser trial is implied by a passing Python test.

## Observe on ordinary work

Use a fresh session after updating. An explicit low-risk style change should be implemented
by Simple, an accepted page redesign by Routine, and a known browser journey by a cheap
operator rather than repeated main clicking. Main must inspect running visuals and send
its findings back as a correction task, then inspect the new evidence. A judgment-only
request should remain main without unnecessary workers. Missing tool access should produce
a narrow truthful limitation, not a generic expensive takeover. No new mandatory trial
blocks direct named work. Compare satisfactory outcomes and total allowance including
setup, review and rework, not just fewer main turns or a larger delegation percentage.
