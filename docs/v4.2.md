# Smart Orchestration 4.2.0

**Preserve intelligence. Remove avoidable coordination. Make evidence trustworthy.**

This release adapts the supplied Cherny-inspired harness note and Atul's Jev/decision-model article,
using the owner's targeted 4.0.1 audit rather than the earlier collector's misleading aggregates.
The eleven model/effort presets, owner-selected Main, five-worker policy, inherited sandbox,
independent gates and lossless installer are retained. There is no 4.1 prerequisite.

## What the audit changed

The apparent fourteen-worker peak was a root turn copied into fourteen child logs. The inspected
episode's genuine own closed worker turns peaked at five. This does not prove simultaneous model
compute or resolve historical open-thread occupancy. Multiple native cap namespaces, persisted
threads and work-completion messages do not establish effective admission or closure.

The large investigator-tagged group contained several legitimate assignments and experiments,
including implementation. Some public ownership transfers were visible; encrypted original briefs
limited authorization/routing reconstruction. It was not established as duplicated investigation.
Tester authored and repaired review artifacts beyond procedural execution. No product-file patch
by that Tester was established. The remedy is explicit suitable duties, not an accusation of
unauthorized work or a blanket model downgrade.

Sampled command repeats included a process-status query, changed-input revalidation, legitimate
RED/GREEN and focused browser fixture/locator repairs. One wrapper exited zero while its internal
receipt reported failed tests. The six purposively selected implementation assignments were
consistent with their depths. These findings support neither a weekly waste rate nor a target
Luna percentage. Private paths, thread identities, raw transcripts and audit files are not shipped.

## Changes

### Explicit assignment boundaries and native lifecycle

[handoffs.md](../codex_workflow/handoffs.md) defines material transfer records: requirement,
actual native owner/preset, duty, risk, source/resource scope, authority, candidate/evidence,
repair history and remaining gates. Related correction context is reused. An unavailable native
role change is not faked in prose; the correct named role or authorized Main takes the work.
Tester executes selected checks/setup; new check design, browser helpers and diagnosis receive
appropriate ownership even when their files are ignored artifacts.

`runtime/work_contracts.py` provides optional `transition` and `capacity` decisions from existing
facts. It rejects conflicting roles, active-owner transfers and writing into a held candidate;
retains counters and gates; and normalizes an explicitly supplied native limit with primary-thread
inclusion and same-domain occupants. It grants no permission, authenticates no observation and
never claims to enforce a native cap. The existing allocator still checks scopes/reservations.
No setting is copied into V2 namespaces or raised automatically. Historical occupancy remains
unresolved until actual native evidence establishes it.

### Reliable, create-only verification receipts

[receipts.md](../codex_workflow/receipts.md) integrates existing project/CI evidence first. The new
optional `runtime/verification_run.py` previews an explicit batch and executes it only with
`--apply` under existing command authority. It uses argv, not implicit shell expansion, retains
original process status, stops after unexpected outcomes and marks remaining gates not_run.
Before/after listed-input fingerprints and uniquely named private logs/receipts prevent this
helper from overwriting prior failed attempts. Timeouts, output limits, drift and contradictory
embedded exit markers prevent a clean process receipt. Expected RED remains nonzero evidence.

A cooperative lock covers identical plans using the same tool/evidence parent only. It is not a
native/global process registry or filesystem sandbox. Use an existing running process handle,
not a second supervisor. Process exit is not test discovery, coverage, external state, visual
acceptance or semantic correctness. Candidate hashes cover listed inputs and cannot detect a
transient modification that was reverted. No CI/stop hook automatically reruns full suites.

### Scoped standards and reviewer evaluation

[standards.md](../codex_workflow/standards.md) adapts the useful Jev methodology without installing
Jev, Perplexity or a second review team. The existing Reviewer sees only relevant mistake/fix/
reference/exception criteria plus the original requirements and candidate. Mechanical checks
remain preferred. Project standards stay project-scoped, separate from Smart operating policy.

`runtime/review_rules.py` selects canonical prefix scopes across changed and declared impacted
paths. Unknown impact widens selection. It excludes fixture corpora from normal briefs and hashes
catalog wording plus cases. `fixture-inputs` prepares development or holdout questions without
expected labels; `score` checks separately supplied model/effort predictions and reports missing
cases, misses, false alarms and abstentions. Nothing calls a model or external API. Passing a
synthetic plumbing test is not a measured reviewer capability or an accepted project change.

The source [example catalog](../examples/review/rules.json) uses synthetic violating, corrected,
harmless-neighbor, exception and missing-evidence cases. Use actual approved standards and reviewed
labels for a real project evaluation. No external data sharing, automatic calibration or probability
threshold as a safety guarantee is introduced.

### Communication and durable lessons

One compact assignment and one evidence-backed handoff replace fragmented instructions and
repeated no-change acknowledgements. Real blockers, ownership conflicts, decisions and meaningful
new evidence still get surfaced. Main does not acknowledge every worker update. Logs remain
available outside the hot context, with concise pointers and decisive failure excerpts.

A repeated verified defect becomes a regression check where possible. Mechanical invariants
belong in a validator; stable non-obvious conventions belong in the correct instruction scope.
Temporary hypotheses stay in the task checkpoint. Global changes require reviewed evidence,
not automatic accumulation of rules after every ordinary error. Tiny tasks require no catalog,
receipt wrapper, task database or persistent checkpoint. Helpers replace work, not add ceremony.

### Collector 1.2.0, separate from installed runtime

The source-only [offline collector](../tools/stats/smart_weekly_stats.py) retains existing privacy
and token accounting, with targeted fixes:

* Exclude ancestor turn identities and precreation logical payload intervals even when physical
  replay timestamps are recent. Missing birth/start evidence cannot certify worker overlap.
* Recognize executable positions in a conservative shell subset, not test words inside process
  filters, echoed text or quoted arguments. Unsupported constructs stay a coverage limitation.
* Keep native wrapper exits separate from embedded exit markers and unresolved test verdicts.
  A zero wrapper conflicting with a nonzero marker is exposed rather than called a test pass.
* Export both sources/lines of repeat pairs and clearly label sampling/candidate uncertainty.
  Do not infer unchanged inputs, false model routing, wasted time or savings from those pairs.

Its regression fixtures are invented. The owner's complete historical raw logs were not rerun
in this release; prior aggregate totals are not silently replaced with new claimed measurements.
The collector is not installed into CODEX_HOME, autostarted or used as mandatory telemetry.

## Helper protocols

The installed guides are sufficient for ordinary use. These helpers are optional structured paths,
not a requirement to serialize every task. They use Python 3.11+ standard library and bounded inputs.

### Transition and capacity

```json
{"operation":"transition","facts":{"task":"T","assignment":"A2","from_owner":"child-a","to_owner":"child-b","from_role":"investigator","to_role":"routine_executor","purpose":"implementation","risk":"low","previous_work_stopped":true,"candidate_held":false,"authority_ref":"owner/task","scope_ref":"scope/v2","requirement_ref":"requirements/v1","evidence_refs":["failure/original"],"pending_gates":["independent-review"],"failed_fixes":1,"repair_rounds":1}}
```

Purposes: implementation, diagnosis, check_design, test_execution, semantic_review, lookup,
checkpoint, known_operation. Evidence references are not authenticated grants. Use a new native
owner for a changed preset; same-role coherent context reuse is retained.

```json
{"operation":"capacity","facts":{"domain":"root/backend","evidence_ref":"native/status","observation_current":true,"effective_limit_verified":true,"native_limit":6,"primary_included":true,"owned_open_workers":2,"other_occupants":0}}
```

This hypothetical example yields at most three more workers before allocator checks. It does
not assert that any particular client uses this domain. Unknown values are null; false or unknown
native facts request inspection. Completed but unclosed owned agents remain in owned_open_workers.

### Verification batch

Use the source [plan example](../examples/verification-plan.json), replacing its illustrative root,
input paths and argv with approved project values. Create the evidence parent through the normal
authorized setup before running the helper.

```text
python3 -B codex_workflow/runtime/verification_run.py --plan PLAN --evidence-parent DIR
python3 -B codex_workflow/runtime/verification_run.py --plan PLAN --evidence-parent DIR --apply
```

A clean receipt means expected process outcomes with unchanged listed inputs, not acceptance.
Private logs/plan may contain sensitive command output; no automatic share archive is created.

### Scoped rules and offline evaluation

```text
python3 -B codex_workflow/runtime/review_rules.py --catalog examples/review/rules.json select --changed src/runner.py --impact-known
python3 -B codex_workflow/runtime/review_rules.py --catalog examples/review/rules.json fixture-inputs --split holdout
python3 -B codex_workflow/runtime/review_rules.py --catalog examples/review/rules.json score --predictions RESULTS.json
```

Predictions schema: schema=1, catalog_digest, model, effort, run_ref and results with rule_id,
case_id, verdict and evidence. Missing, duplicate, unknown, stale or unsupported results cannot
be counted as complete successful evaluation. Labels still require independent review.

## Validation and limits

Run the existing current suite, exact historical migrations, and separate source-only collector
suite. Regression scenarios exercise role expansion, Tester check design, held candidates,
original exits, masked failures, stable private evidence, concurrent duplicate batches, timeouts,
scoped rules, holdout separation and all three demonstrated collector errors. Upgrade/no-op/rollback
coverage includes the exact released 4.0.1 commit and the later main baseline.

No real-project model benchmark, reviewer comparison, account allowance measurement, native V2
qualification or historical test rerun is claimed. Measure accepted outcomes and complete workload
cost after ordinary use. A reduction in prompt words or model messages alone is not a quality or
savings result. Do not weaken required tests or downgrade serious tasks based on biased samples.

## Sources and adaptation boundaries

* Supplied Cherny-inspired research-note image: independently authored adaptation, not an official
  endorsed prompt. Adopt executable checks, compact handoffs and verified lessons; not mandatory
  plan approval for every edit, permanent rules for every error or endless stop-hook retries.
* [Anthropic best practices](https://code.claude.com/docs/en/best-practices): targeted context,
  verification, selective planning and concise persistent instructions.
* [Atul's decision-model article](https://blog.a7ul.com/agents-code-your-way.html): scoped
  mistake-oriented rules, reference examples and labelled cases. The article says its deployment
  uses Perplexity's decider; Smart adds no decider service, cost claim or external dependency.
* [Codex subagents](https://developers.openai.com/codex/subagents/) and
  [hooks](https://developers.openai.com/codex/hooks): verify actual installed-client support and
  effective configuration. Documentation does not resolve historical private runtime occupancy.

Installation remains complete pinned source -> preview -> apply -> check -> manual restart and
fresh conversation. Preserve Main/model/effort, permissions, profiles, explicit limits and backups.
The existing explicit five-worker opt-in remains, but never guess native V2 setting precedence.

### Correction-review continuity

The transfer adviser accepts optional review_baseline_ref only for a retained same-role reviewer
checking a held candidate. It preserves that reference without treating it as authenticated
independence or acceptance. A missing baseline, changed reviewer/role or released hold cannot
use this shortcut; the existing allocator and review contract remain binding. Fixture scoring
counts an incorrect not_applicable response to a true violation as a miss, and a violation
reported for a labelled exception as a false alarm. Abstentions remain separate.
