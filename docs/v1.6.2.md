# v1.6.2: Work/Codex credit economics and Luna-first routing

## Why this patch

v1.6.0/1.6.1 tuned model capability and reasoning effort from GPT-6 guidance and
launch benchmarks. v1.6.2 updates the economics model to use pricing that actually
applies to ChatGPT Work/Codex instead of API-dollar token prices.

Primary source:
https://developers.openai.com/codex/pricing

As of 2026-09-22, Standard Work/Codex credit rates per million tokens are:

| Model | Input | Cached input | Output |
| --- | ---: | ---: | ---: |
| GPT-6 Luna | 2.5 | 0.25 | 12.5 |
| GPT-6 Sol | 50 | 5 | 250 |
| GPT-6 Astra | 250 | 25 | 1,250 |

Sol is 20x Luna and Astra is 100x Luna per token in each category. Fast mode is
2.5x the Standard credit rate for GPT-6 Luna/Sol/Astra where available.

These rates still do **not** convert directly into remaining included weekly
allowance. OpenAI says local messages and cloud chats share plan usage and weekly
limits may apply. Message estimates vary with task complexity, context, tools and
reasoning.

## Pro message estimates

OpenAI currently publishes approximate local-message ranges per five-hour window:

| Model | Pro 5x | Pro 20x |
| --- | ---: | ---: |
| GPT-6 Astra | 25-225 | 100-900 |
| GPT-6 Sol | 70-700 | 300-3,000 |
| GPT-6 Luna | 1,750-14,000 | 7,000-56,000 |

The large Luna/Sol gap supports the architecture but is not an unlimited claim or
a guarantee of completed tasks.

## Routing policy change

The model/effort map is unchanged from v1.6.1. Policy now makes
**Luna-first / Sol-exceptional** explicit. Default Luna Max owns hard bounded
implementation. Senior Sol is for inherently judgment-heavy/high-impact work,
material ambiguity, or a demonstrated capability gap. Difficulty alone and "to be
safe" are not escalation reasons.

Clearly Sol-shaped work can start Senior. Smart does not force a wasteful Luna
failure when stronger judgment is known to be necessary.

## Speed policy

Standard remains the baseline. Smart warns when Fast is configured because GPT-6
Fast consumes credits at 2.5x Standard, but it never silently changes owner speed.
Fast is for latency-sensitive work, not the default path for more throughput.

## Diagnostics change

`runtime/efficiency.py` now reports Work/Codex credits instead of API-dollar
references. It exposes current credit rates, 20x Sol/Luna and 100x Astra/Luna
economics, the 2.5x GPT-6 Fast multiplier, published Plus/Pro five-hour message
estimates, token-workload credit references and read-only configuration diagnostics.

It still cannot infer remaining weekly quota from tokens.

## README rewrite

The README is now a current architecture document rather than accumulated release
notes. It explains main ownership, every worker tier, Luna-first escalation, Pro
message estimates, credit economics, speed, caching, design ownership, verification,
memory, installation and safety in one coherent view.

## Preserved behavior

v1.6.2 changes no named worker model or effort. It does not change owner-selected
parent model/effort, Plan effort, speed, permissions, Computer Use/History, project
files, verification gates, memory behavior or reporting opt-in policy.

## Validation contract

v1.6.2 adds exact credit-rate/ratio/fast-mode tests, README/current-policy contracts,
and exact merged v1.6.1 upgrade/reapply/rollback coverage. Earlier suites remain in
CI. Static tests establish configuration and migration behavior, not model benchmark
reproduction or plan-lifetime forecasts.
