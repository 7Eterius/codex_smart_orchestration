# 3.0.0: balanced intelligence and useful parallel work

Reviewed baseline: 2.7.1 at `2a82aefc381eebab769b38749bba648ad41a8161`.
The owner reported that actual use was satisfactory but slow, especially small tasks and Luna
problem-solving. This is user feedback, not a new measured performance study.

## Findings and changes

The old policy and bootstrap required delegation of tiny edits and review fixes. The allocation
helper enforced a two-thread ceiling. Its normal implementation lane was Luna High; hard work
went to Luna xhigh. Those were intentional economy choices, not installation defects. They no
longer match the owner's desired latency/intelligence balance.

3.0 removes compulsory handoffs for understood small work. Main may implement or own a
context-heavy critical path; meaningful independent tasks go to workers. Default, Tester and
Investigator move to GPT-6.1 Sol Medium. Senior remains Sol xhigh. Simple stays Luna Low,
Routine Luna High for prescribed bulk changes only, Companion/Archivist Luna Medium. No new role.
A configured model's availability must be observed, never invented or silently downgraded.

Luna Max is not made the default for ambiguity. It is optional owner-selected reasoning for a
suitable well-specified task, not a required rung before a more capable solver. One repeated
defect without progress after an evidence-based correction triggers bounded diagnosis/ownership
reassessment; ordinary repair remains local. No automatic Fast or unapproved model tier.

## Parallelism with explicit boundaries

The allocator now permits up to four owned open threads with explicit canonical scopes and
Main activity. It checks read/write overlaps across nested workspace roots, shared mutable
resource identifiers, accepted dependencies, stopped/held candidates and retained ownership.
Unknown peer scopes block unproven parallel work. Same-unit writer exclusion, strict actor
checks, actual capacity and closure evidence remain. No filesystem/process operation is added.

A future independent-review slot is shared across waiting writers rather than reserved once
per task. Reservations must be carried in observations. Ready review/integration can pipeline
without a wait-for-all barrier. Main may proceed on a truly disjoint path. Same desktop/browser,
mutable preview, account, shared styles or lockfile cannot be considered independent by filename.

Fresh absent defaults are cap four and Sol Medium generic children. All explicit older values
remain unchanged, including cap two/three and an older generic fallback. Configuration assessment
reports the bottleneck and recommendations without claiming observed runtime selection.

## Main-authored work still has independent review

The previous boundary checker required primary, writer and reviewer all to differ. That would
reject Main-authored work even with an independent reviewer. 3.0 allows primary=writer but
still requires reviewer distinct from both, correct actor, held candidate, exact verdict
identity, every gate and fresh evidence. This changes the ownership contract, not evidence rigor.

Verification is proportional to risk and owner/project requirements, not the Default role's
name. Initial independent review is full bounded review. Same-reviewer delta reuse retains its
baseline, dependency/impact checks and mandatory fresh gates. Main fixes and concurrent changes
must be included. Main's actual visual acceptance and protected design authority remain.

New compositions use early visual checkpoints when valuable; established small tweaks need not
acquire extra checkpoints or a separate reviewer. The optional candidate/challenge/evidence
helpers remain unchanged except for the boundary ownership rule. No mandatory ledger/preflight.

## Source/test refactoring

All installed guides, named roles and the managed bootstrap now agree with the 3.0 route.
Existing installer transaction, fingerprints, ownership markers and rollback mechanisms remain.
Prompt size limits are retained, not raised.

Architecture-specific 2.x tests are replaced by current behavioral suites. Exact 2.7.1 source
and its unchanged 309-test suite are run in isolation as a historical reference, explicitly
separate from current-code validation. Candidate, hardening and publication regressions remain
active; current evidence/installer tests are regrouped. Migration tests use real archived
installers from 1.9, 2.3, 2.4, 2.5, 2.6, original/reviewed 2.7 and 2.7.1, then upgrade to 3.0,
reapply with no changes and roll back byte-for-byte. CI requires the Git history.

Current tests include tiny Main fixes, novel versus mechanical browser routing, material-risk
review, stalled cheap work, parallel scopes/resources/Main conflicts, accepted dependencies,
shared review capacity, holds, no hidden scope widening, native closure/no-blind-retry,
Main-written independent gates, stale/unknown evidence, malformed CLI input, local-edit
protection and preserved explicit owner configuration.

These source tests do not prove live model compliance, native tool access, an actual speedup,
semantic correctness of future work or reduced subscription consumption. The allocator is a
prospective check over supplied facts, not a scheduler, lock or authenticity boundary.

## External guidance used

Primary OpenAI documentation checked during this review:

- [Subagents](https://developers.openai.com/codex/subagents): explicit parallel work, subagent
  overhead, Sol for demanding tasks and Luna for clear repeatable work.
- [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol): model/effort contract.
- [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): model/effort contract.
- [Configuration reference](https://developers.openai.com/codex/config-reference): open spawned
  threads, primary exclusion and legacy max_threads alias.
- [Latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization):
  reducing unnecessary work and requests and exploiting independent work.

This guidance supports the design direction; it is not a controlled Smart 2.7.1-versus-3.0
benchmark. Higher token prices can be offset by fewer calls/retries, but need not be. Preserve
quality and measure elapsed time to accepted result, rework and total allowance usage together.

## Installation

Use the existing pinned-main preview/apply/check procedure, manually restart and start a fresh
conversation. Existing explicit capacity and models stay preserved. The published repository
changes no local client. Version tag and checksum identify a source artifact, not live activation.
