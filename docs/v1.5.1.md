# v1.5.1: better judgment boundaries, not another workflow

Scope: retain the eight model/effort tiers, independent Tester, global installation,
three-child absent default, isolated capsules, raw-backed logs and parent acceptance.
This patch changes no parent model, speed, permissions, application source or store.

## Five bounded refinements

1. Context depth follows uncertainty: before writing unfamiliar modules, map callers,
   dependencies, invariants and tests. Resolve assumptions that could change the
   contract, ownership or acceptance. Whole-system audits need broad evidence.
   Familiar settled tasks do not acquire a mandatory project survey.
2. Executors diagnose ordinary compiler/test defects and continue while new evidence
   advances the contract. Stalled progress or a material decision produces a compact
   escalation, not a parent turn for every failure or an arbitrary retry quota.
3. For novel/high-impact work, use the same independent Tester early to identify
   invariant, denied and failure cases, then again for final verification. This is
   conditional, not another mandatory reviewer or a waiver of final tests.
4. Archivist preserves verified reasons and rejected approaches when they affect
   future choices. Reuse existing canonical decision/architecture/lesson documents
   and link from the current handoff. Do not invent rationale or require new files.
5. Installer and doctor share config_assessment.py. Known malformed settings and
   agents.enabled=false are errors. Explicit cost choices are warnings. Effective
   runtime/profile/child behavior stays unverified. Normal and Plan-mode effort are
   displayed independently, not inferred from one another.

## Legacy configuration and diagnostics

Previous installation code interpreted false for either legacy feature/backend
flag as proof that all subagents were disabled, while doctor missed those flags.
That inference is not portable across Codex versions. v1.5.1 preserves each legacy
flag, reports a compatibility warning and marks its runtime effect unverified in
both tools. It never enables a flag or changes permissions. Explicit root
agents.enabled=false still blocks installation and is an error in doctor.

Doctor `ok` now means no detected on-disk errors, not no warnings and not confirmed
live activation. `issues` remains a compatibility alias for errors only. Missing or
malformed worker files and missing recursion controls are errors. A well-formed
owner worker edit is a warning; the installer still refuses to overwrite it without
review. A deliberate Fast setting or concurrency above three is not corruption.
No installed/profile configuration, logs or user instructions are rewritten by doctor.
No profiles, repositories, sessions, account usage or environment secrets are read.

## Sources verified 2026-09-15

- https://developers.openai.com/codex/config-reference/
  Documents agents.enabled, the legacy max_threads alias, child defaults and the
  separate plan_mode_reasoning_effort setting. Unset Plan effort uses its built-in
  preset. This patch does not hard-code a current preset value.
- https://developers.openai.com/codex/subagents/
  Describes role configurations and delegation. No model self-report is treated
  as independent evidence of effective settings.

Legacy backend-specific flags are intentionally not interpreted as a universal
runtime truth. The shared assessment is not a replacement for Codex schema or a
probe of the running client's behavior.

## Validation and release qualification

Run all prior suites plus `python3.11 -B scripts/test_v151.py -v`. The new suite
covers error/warning separation, malformed settings, legacy-flag preservation,
normal/Plan effort distinction, read-only reporting and a real v1.5.0-to-v1.5.1
upgrade, repeat install, exact rollback and project preservation. Its baseline is
Git commit 2d640f78831644872c1fe521d452da08c0a08855. A local test may supply an already
byte-verified CI baseline via SMART_V150_BASELINE; CI reconstructs it from full Git
history. Two old v1.5 test assertions now track VERSION, retaining their readback
checks. The new suite explicitly asserts version 1.5.1 and all eight capability tiers.

CI and release workflows run the new suite before packaging. Installation still
uses the existing global smart_install.py and named backup/rollback mechanism.
Publish only the archive built from the reviewed passing commit, identified by its
checksum. A build or PR is not a published release. Do not replace old-version bytes.

## Manual behavior scenarios: not automated or claimed executed

| Scenario | Expected behavior |
| --- | --- |
| Approved low-risk label correction | Scoped implementation/check; no broad survey or Senior by ceremony |
| Small financially significant change | Parent resolves relevant invariant before delegation |
| Ordinary compiler failure | Existing Executor diagnoses/repairs within scope |
| Unclear entitlement boundary | Early Tester failure/denial cases; parent resolves requirement gaps |
| Missing external credential | Honest blocker; no model-tier retry loop |
| Return to a settled design | Retrieve recorded rationale; no renewed competition without owner direction |

Record actual decision and final accepted evidence when piloting these scenarios.
Text assertions and software tests do not establish live routing quality, equivalent
output quality or a five-day allowance result. Keep the model baseline stable and
measure accepted tasks including repair and rejected visual results.
