# Smart Orchestration 2.3.0

One adaptive workflow, with hardened ownership and checked review boundaries.
Prepared from v2.2.0 commit `53454e4f87227c88c4132d8021b3d6f14fe06c63`.

## Correctness fixes

- Apply the single-writer guard to mutation-bearing reuse as well as new dispatch.
  Explicit readback of a stopped matching worker remains possible without write authority.
- Validate the primary/caller distinction, live owned caller state, same-unit nested
  review and explicit scheduling authority. Cleanup of eligible old children remains
  possible for completed/retired owners without enabling new delegation.
- Normalize malformed candidate schema types and excessive JSON nesting into declared
  errors. Preserve all batch dispositions instead of crashing before later drift/matches.
- Detect physical manifest aliases through canonical paths and device/inode identity.
  Aliases are individual errors, not additional matched evidence. Missing/unreadable
  paths remain individual outcomes; lexical duplicates retain fail-fast input validation.
- Reconcile the stale concurrency warning with the two-owned-thread operating target.

## Checked boundaries and economical operation

The optional [boundary checker](https://github.com/7Eterius/codex_smart_orchestration/blob/v2.3.0/codex_workflow/boundary.md) validates an existing
independent-review capsule and a separate Tester verdict. It checks unit/attempt/contract/
candidate/target identities, distinct writer/reviewer roles, candidate holds, exact gate
maps and mandatory fresh execution. Required failed, blocked, unrun, deferred or
not-applicable gates cannot silently become acceptance.

Main returns for decisions, authority, genuine blockers and acceptance, not routine
message relays. Repair handoffs name the failed requirement, evidence, allowed delta
and fresh checks. Repeated attempts need new information or changed diagnosis. Context
and guide loading stay scoped. An [optional evaluation worksheet](https://github.com/7Eterius/codex_smart_orchestration/blob/v2.3.0/docs/evaluation.md) supports
comparison of complete accepted outcomes without mandatory telemetry or a new service.

The eight role model/effort configurations, parent choices, permissions and configured
concurrency remain unchanged. No Normal/Coordinated modes, manager layer, automatic
model escalation, background daemon or per-command accounting are introduced.

## Compatibility and installation

Use the [source installation procedure](https://github.com/7Eterius/codex_smart_orchestration/blob/v2.3.0/README.md#installation-or-update).
The installer includes the new boundary helper/guide in its fingerprint, preserves
unrelated configuration and project files, and retains conflict-checked rollback.
Exact v2.2 -> v2.3 -> rollback is covered alongside the existing historical migrations.

Allocation callers using the literal legacy `main` continue to work without a primary
field. Real native handles should supply `primary` explicitly. Nested owners must now
supply `review_authorized: true`; absent/false authority cannot authorize new review work.
Requests may explicitly choose work, readback or cleanup as documented in the guide.
Candidate scope/file metadata rejects unknown nested fields; versioned schema 1 output
from the existing snapshot command remains supported.

## Verification and limits

Regression tests cover the audited defects, malformed inputs, aliases, cleanup and
caller boundaries, holds, stale verdicts and gate obligations. CI runs the complete
suite with full Git history on Ubuntu/Python 3.11, Ubuntu/Python 3.12 and macOS/Python 3.12,
plus compilation and changed-commit whitespace checks. Release publication is gated on
that matrix. The release workflow identifies its tested commit and CI run in the notes.

These are source/installer/helper checks, not live Codex qualification. No native
owner-to-Tester spawning, model selection, permission inheritance, closure/reclamation,
pause propagation or subscription savings are claimed by this release. Follow the
[targeted runtime protocol](https://github.com/7Eterius/codex_smart_orchestration/blob/v2.3.0/codex_workflow/runtime_check.md) in an authorized private
client fixture. Keep PASS, FAIL and UNVERIFIED separate. The earlier 2.1 failure is not
retroactively resolved by publishing 2.3.
