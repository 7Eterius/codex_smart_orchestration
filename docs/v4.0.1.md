# Smart Orchestration 4.0.1

A focused bugfix to the released 4.0.0 source at
`332da7c08adfce2ac4d24d8a4a9a69dae3ebe017`. The eleven model/effort presets, Main selection,
five-worker policy ceiling, sandbox inheritance, installer safeguards and quality gates are
unchanged. No new orchestrator, daemon, dependency, agent or mandatory ledger is added.

## Verified defects and repairs

### Budget arithmetic at decimal boundaries

Binary floating-point subtraction could reject an exactly fitting budget: maximum 0.3,
spent 0.1 and next batch 0.2 returned replan_budget. It could also erase a small real overrun:
maximum 1, spent 1e-18 and next batch 1 incorrectly proceeded. The adviser now compares the
supplied decimal representations with standard-library rational arithmetic. This does not
make a model's cost estimate accurate or turn supplied quota facts into authenticated metering.

### Circuit-breaker recovery without erasing history

The 4.0 policy allowed Main to record a new approach and bounded attempt budget after a breaker.
The helper had no corresponding resume input: cumulative counts of three always returned replan.
It now accepts an optional identity-bound replan record. Cumulative counters remain intact;
the new window consumes deltas from its recorded baseline. A model/worker change alone never
resets the window. New evidence, budget and authority checks remain mandatory, and a blocker
never becomes accepted simply because a repair budget expired.

Example addition to existing recover facts:

```json
{"replan":{"task":"T1","defect":"D1","decision_ref":"notes/T1#new-cause","failed_fixes":3,"repair_rounds":3,"attempt_limit":1}}
```

The record must name the same task/defect, a nonblank Main decision reference, current cumulative
counter baselines and an integer attempt_limit from 1 to 3. Future baselines are rejected.
remaining_attempts uses the larger counter delta because one failed repair may advance both
counters. A newly recorded replan can acknowledge the preceding no-progress result only at its
exact baseline; a later stalled attempt still escalates. The reference is supplied evidence,
not an authenticated signature. Main must actually review and record a new approach; do not
manufacture a replan merely to keep trying. Counters remain in the existing task note/checkpoint.

### Low-quota throttling includes existing workers

The old helper limited only new workers in one batch. Repeated low-quota batches could therefore
accumulate workers. An optional open_workers observation now subtracts already-open Smart-owned
workers from the quota ceiling. Count waiting/completed workers until native closure; this patch
never closes them itself. The allocator's actual capacity, ownership, resource and review-slot
checks remain separate and binding.

New callers should provide open_workers from existing observations. For backward compatibility,
omission retains next-batch-only behavior but now explicitly returns limit_scope=new_batch_only.
A supplied count returns total_open_workers; explicit null requests capacity inspection. This is
not a native concurrency lock and does not know about sessions omitted from the supplied state.

### Repair ownership and read-only work

With new evidence, recovery previously returned may_patch=true even for Tester, Reviewer,
Investigator and lookup/checkpoint roles. It now returns assign_implementation and may_patch=false
for those roles. Transfer to an implementation owner through the existing allocation/authority
process. This is a method recommendation, not a new permission grant.

Research or writing about code without a behavior change no longer loads test/worktree setup
methods merely because domain=code. Actual behavior changes still select the appropriate tests,
and explicit project/owner TDD gates remain binding. This reduces irrelevant ceremony without
changing acceptance criteria.

### Input handling and honest diagnostics

The CLI checked a path before opening it. A file replaced by a symlink in that interval could
still be followed. On supported POSIX hosts the reader now uses no-follow/nonblocking flags,
checks the opened descriptor is a regular file, retains the 64 KiB read bound, and closes the
descriptor on failure. A replacement FIFO cannot block waiting for a writer. This is final-path
hardening, not a full filesystem sandbox or protection against every ancestor/concurrent race.
Unexpected programming TypeError is no longer disguised as malformed user JSON; ordinary input
and filesystem failures still return structured errors.

## Protocol and compatibility

All previous required input fields remain supported. New fields are optional and strictly
validated before short-circuit decisions. New output fields are open_workers, limit_scope,
remaining_attempts and replan_ref. assign_implementation is a non-proceeding result (CLI exit 1).
Exit 0 remains bounded advice only; it is never permission, native scheduling or acceptance.
Missing/invalid evidence cannot satisfy independent gates.

The installed debugging and economics guides describe the additions. These helpers remain optional;
do not introduce per-command bookkeeping, recurring audits or workflow retuning for ordinary work.
No changes to model prices, role effort, five-worker defaults, ownership rules or review standards
are part of this patch. The owner-authorized five-worker installation option remains available.

## Validation

Regression cases were first run against a local copy whose Git blob hash matched the exact
published 4.0.0 delivery.py (`49c37d593815972640951c115c807137c39d50df`). They reproduced the
precision, recovery/input and role-boundary gaps. The repaired helper passes the targeted cases.
The full CI suite also executes the exact historical 4.0.0 source for counterexamples and adds
4.0.0 to upgrade/no-op/exact-rollback coverage. The separate archived 2.7.1 tests stay unchanged.
The normal Linux Python 3.11/3.12 and macOS Python 3.12 matrix must pass before publication.

Source tests establish deterministic helper and installation behavior, not live Codex compliance,
actual model availability, future client compatibility or measured task latency/allowance savings.
No user-Mac installation or configuration change is performed by this repository release.
