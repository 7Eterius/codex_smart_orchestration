# Smart Orchestration 1.5 system audit

## Basis and scope

The owner's supplied 14-point multi-agent best-practices checklist was evaluated
against v1.3.2, not treated as a set of automatically correct configuration edits.
The checklist's principle is retained: spend intelligence on difficult decisions
and minimize the repeated context needed to reach them. This audit preserves its
ranked practice names. External verification and implementation choices are marked
separately. User source material and private project content are not published.

This revision includes the complete v1.3.2 change-aware verification and raw-log
capture work. It is not a separate route. Main still plans and seriously audits;
Luna tiers, independent verification and permanent Archivist memory remain.

## Additional whole-system findings and fixes

1. Global output-path substitution previously ran over the entire generated
   AGENTS text, including surrounding owner instructions. v1.5 substitutes only
   the managed region; owner text containing ~/.codex remains byte-preserved.
2. Generic child defaults were absent even though named workers had pinned tiers.
   Missing defaults now receive Luna Medium and a concurrency cap of 3. Explicit
   owner values and legacy max_threads aliases stay intact and are diagnosed.
3. Recursive delegation was only a prompt instruction. Named child configs now
   disable multi-agent tools. This is not a universal security boundary against
   arbitrary executable code; normal permissions and no-bypass policy still apply.
4. Customized reporting-skill files could be overwritten if their ownership marker
   remained. Compare against installed templates and refuse custom modifications.
   Extra installed notes are preserved rather than deleted as unshipped files.
5. Scanning every unrelated skill/agent symlink could block valid plugin setups.
   Only managed targets are checked; symlinks in owned paths remain forbidden.
6. Historical source snapshots could be replaced under the same version number.
   Different existing bytes now block adoption. Reapply uses the pristine source
   snapshot, not the assembled installed runtime with generated state.
7. Newer updates could be validated using an old launcher's schema. The verified
   incoming release now owns update validation and installation.
8. There was no tested exact rollback command. A named backup can now be restored
   after before/after hashes, allowed paths and conflicting newer edits are checked.
   Restoration itself is backed up. No force or whole-home deletion exists.
9. Basic status reported file presence, not a useful integrity check. A read-only
   doctor checks defaults, known worker/template matches and recursion controls.
   It deliberately distinguishes disk configuration from observed live operation.

## Choices deliberately NOT made

- No arbitrary shrinkage of context windows, lower Tester effort, new tiny log-
  analysis model, or forced low-tier failure for known hard work.
- No new pricing or quota formula. The attached API examples are not a plan-wallet
  budget. Five working days still requires observed accepted-task measurements.
- No unsupported global fork_turns config key; the runtime tool argument is a
  behavioral requirement. No universal claim about every installed Codex version.
- No blanket removal of accessibility, localization, build or security requirements.
- No third-party output proxy, permission changes, hidden MCP disabling, root-model
  replacement, API credential setup or project-wide installation.
- Existing explicit child settings are not silently replaced. Nonstandard inline
  or dotted agents configuration is preserved with a warning instead of a lossy
  TOML rewrite. Use named roles and review those defaults deliberately.

## Evidence and validation levels

Automated checks establish configuration/data-preservation behavior and policy
contracts, not actual LLM judgment. Local and CI test counts are recorded in the
release handoff after execution. Required suites retain inherited runtime tests,
Smart/configuration/efficiency tests, token-report tests, verification/capture
regressions, and v1.5 defaults/recursion/rollback/ownership tests.

Two existing tests need explicit semantics updates: parent-config preservation
now also permits the new absent child defaults, and the symlink refusal fixture
uses an OWNED worker path rather than an unrelated helper. All original owner-
preservation and unsafe-write assertions stay exercised. Earlier documented
legacy policy-text adaptations remain explicit. No failed test is ignored.

No live Codex client/model is available in this test environment. First real tasks
must verify that the session sees Smart Orchestration, configured roles are used,
isolation is observed, and the final quality rubric passes. Installation success
or a model reporting its name is not sufficient proof. This is a general-purpose
baseline, not a guaranteed optimum for all repositories or five days of work.
