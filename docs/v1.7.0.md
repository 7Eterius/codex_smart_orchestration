# v1.7.0: adaptive high-quality workflow

v1.7.0 keeps the entire GPT-6 model/effort ladder from v1.6.3 and changes how those
models collaborate. The goal is lower parent-context and Sol consumption without
reducing verification where independence materially improves confidence.

## Changes

### Senior Sol advisory-first

Senior Sol xhigh now defaults to read-only judgment. It receives the smallest
decisive evidence set and returns Decision, Rationale, Constraints and Next action.
The current Luna writer normally implements that decision.

Production ownership transfers to Senior only when implementation is inseparable
from the hard judgment or a material Luna capability gap remains. Known Sol-shaped
work may start Senior; no forced Luna failure is required.

### Risk-adaptive Tester

Independent Tester is no longer automatic for every substantive edit:
- Simple: local decisive check, no Tester by default.
- Routine: Tester for behavior/state/integration/UI/accessibility/shared-contract or
  cross-boundary impact, or when repository rules require it.
- Default: Tester by default.
- Senior-transferred implementation: Tester by default.

Novel/high-impact work can reuse the same Tester early and at final verification.
Repository and owner gates always override this matrix.

### Compact handoffs

Every worker uses a fixed Outcome/Changed/Checks/Risks result shape; successful
bounded results normally stay within 120-180 words. Senior advice uses
Decision/Rationale/Constraints/Next action. Long logs stay outside parent context.

### Parallelism and context

One production writer per shared mutable boundary remains the default. Parallel
children are limited to genuinely independent work; duplicate reviews need a stated
reason such as competing hypotheses.

A coherent feature stays in one parent context. At an accepted major milestone,
Archivist produces a compact handoff. Substantially unrelated future work should
prefer a fresh main session seeded by that handoff; platform-native compaction is
preferred when continuity is required.

### Optional Luna-parent pilot

No automatic parent switching is introduced. Owners can deliberately experiment
with GPT-6 Luna Max as parent for implementation-only sessions where architecture,
product behavior and design are settled, while keeping Senior Sol advisory escalation.
This is a pilot pattern, not a claim that Luna replaces Sol for ambiguous judgment.

### Prompt slimming

The main Smart policy and all worker instructions are rewritten more compactly.
This reduces orchestration text repeatedly carried in model context while preserving
design ownership, safety, no-recursion, memory, no-statistics, evidence and
acceptance boundaries.

## Unchanged

- Simple Luna Low
- Routine Luna High
- Default Luna Max
- Senior Sol xhigh
- Tester Luna xhigh
- Companion Luna Medium
- Investigator Luna xhigh
- Archivist Luna Medium
- no built-in reporting skill
- Standard-speed preference
- owner-selected parent model/effort
- project-specific safety and acceptance gates

## Validation

v1.7.0 adds policy-contract tests for advisory-first Sol, Tester gating, compact
handoffs, independent parallelism, milestone context lifecycle, optional Luna-parent
pilot documentation, exact model-map preservation and exact v1.6.3 upgrade/reapply/
rollback. All prior active suites remain in CI.
