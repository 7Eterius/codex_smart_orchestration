# v1.6.3: retire deployment-token reporting

Smart Orchestration no longer ships, installs, invokes, documents, or tests the
`deployment-token-report` skill.

The feature was already opt-in in v1.5.3, so retiring it is not expected to recover
the large token totals that old reports measured; those totals described the work
being reported. The retirement still removes skill metadata, accidental invocation,
report interpretation, and maintenance overhead, which matches the owner's preference
to spend the budget on product work rather than orchestration statistics.

## Active workflow changes

- Remove the complete `codex_workflow/skills/deployment-token-report/` payload.
- Remove deployment-report markers and reporting instructions from main policy.
- Remove reporting responsibilities from Archivist.
- Remove reporter-specific CI suites and package requirements.
- Keep permanent project memory; memory is not coupled to usage accounting.
- Keep `runtime/efficiency.py` as a passive local routing-economics utility. It is
  not a skill, is never auto-invoked, and makes no model calls.

## Upgrade behavior

v1.6.3 records an empty built-in skill set. The global installer recognizes skills
listed in the previous Smart ownership manifest but absent from the incoming package
as retired workflow-owned skills. It deletes only those managed skill files and
their generated runtime templates. Unrelated user skills remain untouched.

If the retired skill was already manually uninstalled, upgrade succeeds and does
not recreate it. Historical private rollback/source backups may still contain older
versions so an exact rollback remains possible; those copies are not active skills.

## Preserved behavior

No model or reasoning-effort tier changes. Parent settings, speed, permissions,
projects, Git state, design ownership, independent testing, Luna-first/Sol-exceptional
routing, permanent memory, and project-specific acceptance gates remain unchanged.

## Validation contract

v1.6.3 must verify an empty package skill set, absence of reporting hooks in active
policy/README/Archivist, fresh install without the skill, exact v1.6.2 upgrade that
retires an installed managed copy, upgrade after a manual uninstall, preservation
of unrelated user skills, zero-write reapply, and exact rollback.
