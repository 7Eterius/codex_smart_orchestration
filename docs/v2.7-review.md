# 2.7 source review: coherent evidence and economical correction review

Reviewed baseline: `8b5e5de112dd3c8b468d6a55c81051556124a2ef` (2.7.0).
This is a focused same-version source refinement, not a new execution architecture.
The current main commit and package fingerprint identify the installed refinement;
the original immutable version tag/release is not moved or overwritten.

## Reproduced defects

1. Boundary rejected the documented STALE/UNVERIFIED gate states as malformed input,
   while challenge accepted them as valid unsatisfied evidence. Both now share one
   small `runtime/evidence.py` vocabulary/freshness rule. Negative observations block
   acceptance with the ordinary blocked disposition; they never become PASS.
2. Boundary accepted an executed-pass result whose evidence reference was only spaces.
   Blank/whitespace-only text, control characters and surrogates are rejected; legitimate
   Unicode references remain valid. This validates reference syntax, not evidence truth.
3. A preflight containing enough worker questions could truncate away the protected
   question while still returning decision-needed. Main-route issues are now shown first.
   The manifest-drift path uses the same renderer, preserving actionable routing and
   bounded counts rather than replacing the leading Main decision with a worker refresh.

These defects reproduce against archived 2.7 code. There is no claim that they caused
particular failures or consumed a measured amount of the user's allowance.

## Economical correction review

Initial independent review still reads the original task, complete bounded diff and all
requested deliverables/questions. A suitable reviewer retained through corrections can
instead review every hunk of the delta from its recorded reviewed candidate, the affected
callers/dependencies and original findings, retaining only demonstrably applicable coverage.

A missing baseline, changed contract, unknown impact or new reviewer requires a full bounded
review. Explicit full-review requirements and mandatory fresh execution override the
optimization. This saves repeated investigation where applicable, not required checks.
Main still assesses actual visuals, consequential decisions and final acceptance, then
sends corrections back to the worker. No automatic waiver or delegation quota is introduced.

## Refactoring and compatibility

One internal module holds the shared gate semantics. It has no CLI, state, network, model
call or automatic execution. The existing boundary and challenge commands stay compatible;
malformed references are rejected rather than silently repaired. The installer inventories
and fingerprints the module, protects local edits and removes it on exact rollback.

The Main policy, bootstrap, all model/effort/sandbox settings, eight-role allocation,
run-wide two-thread limit, candidate holds, scope/authority boundaries and browser/design
contracts remain unchanged. No manager, new mode, mandatory ledger or general qualification
ceremony is added. The verification guide remains below its 700-word budget and the Tester
instruction block below 200 words.

## Validation

The new focused suite covers both helpers across every gate status, case spelling and
freshness setting; real CLI exit codes and nonmutation; blank/control/Unicode references;
actionable truncated output; original baseline reproductions; manifest drift; and exact
archived 2.7 installation -> same-version update -> no-op -> rollback. It also checks owner
configuration, project files, role settings and local-edit protection.

Full-history integrations run in CI on Ubuntu/Python 3.11 and 3.12 and macOS/Python 3.12.
Source tests cannot establish native model compliance, review quality or quota savings.
The helper still trusts supplied observations and cannot detect omitted obligations or
forged evidence. Further optimization should follow observed work/rework, not another
layer of orchestration.
