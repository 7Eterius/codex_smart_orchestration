# 2.1: smaller assignment shapes, reusable setup, recoverable handoffs

## Scope and source review

Reviewed on September 24, 2026 against Smart main
`e90d1a513e183cb47598b4ba601e79ab392f0873` (merged 2.0) and Arcana experimental branch
`e7701818173ccf00db5d2f1c2cb149b4822f7f14`. The examined Arcana execution contract is
blob `62054793eebfd172d91e23bc12e1c96f50f3c0e4`, unchanged from our earlier read. These
are refinements found on a second review, not a claim that Arcana just shipped new code.

The Reddit post is the author's observational comparison, not a controlled benchmark
of Smart. It reports fewer invocations of large contexts, not cheaper individual calls,
and explicitly distinguishes API-equivalent cost from subscription billing. Multiple
workflow changes and differing runs prevent attributing a universal causal saving.

## Decisions

1. **Choose topology per assignment.** The top-level run does not force every gate through
   a lead. Mechanical-only work goes directly to Simple, standalone verification to
   Tester, and a substantive review/repair loop can use a lead. Required independent
   validation stays independent. No new role or model changes.
2. **Coherent groups, not microscopic chunks.** Arcana explicitly supports named groups.
   Main may enumerate related member IDs sharing settled context, with separate gates,
   dependency order and a finite stop. Avoid repeated cold starts without recreating a
   permanently growing lead. Approval and rollback boundaries cannot be grouped away.
3. **Fix continuation ambiguity.** The 2.0 core's generic stop-after-report rule could
   also be read as applying to main status replies. 2.1 distinguishes commentary progress,
   final worker handoff, parent run completion, resource release and slot reclamation.
4. **Resource lifetime differs from context lifetime.** A fresh lead can inherit a verified
   server/browser/setup through explicit ownership and consumer transfer. No compulsory
   login replay, installs or full environment inventory per worker. This adopts useful
   resource-lifecycle principles without disk quotas, a daemon or a new ledger.
5. **One gate map and complementary evidence.** Reuse requirement IDs after independent
   coverage/applicability checks. Connect evidence to contract revision and acceptance
   level. Reopen affected gates/dependents; retain unrelated applicable results. Screenshots,
   browser interaction and contract tests should answer different questions where possible.
6. **Recoverable consequential actions.** Arcana records acceptance before commit and
   observed identity afterward. Smart also applies the principle to authorized consequential
   GUI mutations: preserve intent/basis and observed outcome, then reconcile unknown results
   before retrying. This is not an atomic transaction or a per-click journal.
7. **Batch mechanical identity checks.** Add `candidate.py verify-many`, using existing
   manifests without result caching. Retain separate match/drift/error outcomes and bounded
   previews. The helper proves listed input identity, never acceptance or test applicability.

## What is intentionally unchanged

Model/effort tiers, owner-selected parent, nine roles, one delegating role, leaf restrictions,
capacity defaults, risk-sensitive independent validation, design authorship and protected
installation surfaces remain. No custom model catalog, `use_responses_lite` override,
permission relaxation or arbitrary reasoning downgrade is adopted from the community post.
Higher-priority platform update requirements still bind; policy cannot override them.

No new runtime scheduler, JSON handoff database, plugin hierarchy, mandatory telemetry,
disk-threshold policy or automatic browser-cache deletion is introduced. Batching is an
optional extension of a current helper, not a new report each task must generate.

## Verification

Preserve the 2.0 test suite, add batch-helper behavior tests and 2.1 policy contracts,
and exercise a real archived 2.0 package -> 2.1 -> repeat apply -> exact rollback.
Policy text assertions are regression guards, not observed model behavior. The live
qualification procedure separately covers grouping, lean gate routing, status continuation,
stale outcomes, resource handoff and interrupted consequential actions.

Measure total cost per comparable accepted outcome, including every layer, setup, rework,
missed obligations and independent gates. Lower requests/hour may reflect lower throughput.
Keep the extra layer only when it preserves quality and reduces total work.
